## ⚠️ `CREATE_DATE` ≠ `EXTRACT_DATE` — ต้องใช้ `CREATE_DATE`

ตารางนี้ **ถูกโหลดทับใหม่ทั้งตารางทุกวัน** (full snapshot replace)

| คอลัมน์ | คืออะไร | ค่าที่เห็น |
|---|---|---|
| **`CREATE_DATE`** | **วันที่โหลด snapshot** | ทั้ง 329,078 แถวเป็นวันเดียวกัน |
| `EXTRACT_DATE` | **cohort วันเปิดสัญญา** | กระจาย 2026-01-27 → วันล่าสุด |
| `MODIFY_DATE` | — | NULL ทุกแถว |

**หลักฐานว่า `EXTRACT_DATE` เป็น cohort ไม่ใช่วันดึงข้อมูล**

| หลักฐาน | ค่า |

| 1 `CONTRACT_ID` โผล่กี่ `EXTRACT_DATE` | **1 ค่าเสมอ** (329,078 สัญญา = 329,078 แถว) |

## เกณฑ์ที่ใช้

**อยู่ในเขตน้ำท่วม = รหัสอำเภอตรงกับในรายชื่อ** (ไม่ใช่แค่จังหวัดตรง)

จังหวัดตรงอย่างเดียวไม่พอ เพราะหลายจังหวัดไม่ได้ท่วมทั้งจังหวัด —
**นครราชสีมา ท่วมแค่ปากช่อง 1 อำเภอ จาก 32 อำเภอ** · กาญจนบุรี แค่ไทรโยค

| คอลัมน์ผลลัพธ์ | ความหมาย |
|---|---|
| `Map_province_register` / `_current` | จังหวัดอยู่ในรายชื่อไหม (Y/N) |
| `Map_district_register` / `_current` | อำเภออยู่ในรายชื่อไหม (Y/N) |
| `summary register` / `summary current` | สองตัวข้างบนต่อกัน — `YY` `YN` `NY` `NN` (แพทเทินเดิมของ K2) |
| **`น้ำท่วม_ทะเบียนบ้าน`** | **Y เมื่อ `summary register` = `YY`** ← 1 ใน 2 คอลัมน์ที่ขอ |
| **`น้ำท่วม_ปัจจุบัน`** | **Y เมื่อ `summary current` = `YY`** ← อีก 1 คอลัมน์ |
| `ตรงกับที่อยู่` | `ทะเบียนบ้าน` / `ปัจจุบัน` / `ทั้งสองที่` / `ไม่อยู่ในเขตน้ำท่วม` |

| `ภาคน้ำท่วม` | ภาคจากรายชื่อ (เหนือ · ตะวันออก · อีสาน · กลาง · กทม.) |

## ⚠️ ข้อผิดพลาดในไฟล์ K2 เดิม ที่ไม่ทำซ้ำ

### 1. จับคู่อำเภอโดยไม่ดูจังหวัด

`เฉลิมพระเกียรติ` เป็นชื่ออำเภอที่มีใน **5 จังหวัด** — บุรีรัมย์ (`3123`) ·
นครราชสีมา (`3032`) · นครศรีธรรมราช (`8023`) · น่าน (`5515`) · สระบุรี (`1913`)
ท่วมแค่ของ**บุรีรัมย์** แต่ไฟล์ K2 ติด `Map_district = Y` ให้อีก 3 จังหวัดด้วย
รวม **21 แถว** · เช่นเดียวกับ `จอมทอง` ที่มีทั้งใน **กทม.** (ท่วม) และ
**เชียงใหม่** (ไม่ท่วม) — ของเชียงใหม่ติด Y ตามไปด้วย

→ ที่นี่เทียบด้วย **รหัสอำเภอ 4 หลัก** ซึ่งไม่ซ้ำกันทั้งประเทศ ปัญหานี้หมดไปเชิงโครงสร้าง

### 2. ฝั่ง `current` ไม่ได้คำนวณใหม่ — ลอกคำตอบฝั่ง `register` มา

สัดส่วน Y/N ของสองฝั่งเท่ากันเป๊ะทุกช่อง (2,527/2,949 และ 1,640/3,836)

| วิธี substring จะนับ | **191 (ทั้งจังหวัด)** |
| **นับเกิน** | **81** |

อำเภอในอยุธยาที่ไม่อยู่ในรายชื่อน้ำท่วม แต่ substring จะนับให้:
วังน้อย · อุทัย · นครหลวง · ลาดบัวหลวง · ท่าเรือ · ภาชี · มหาราช · บ้านแพรก · บางซ้าย
(อยุธยาท่วม 7 อำเภอ จาก 16)

#### ปัญหา `return` เร็วเกินไป

```python
for province, districts in district_dict.items():
    if province in x:
        for district in districts:
            if district in x:
                return province, district, True
        return province, 'N', False      # ← ออกจากลูปทันที ไม่ดูจังหวัดอื่นต่อ
```

ชื่อจังหวัดที่ติดมากับชื่อซอย/ถนน/ตำบล ทำให้หลุดตั้งแต่รอบแรก

| ที่อยู่ | substring เห็น | จริง ๆ คือ |
|---|---|---|
| `ซอยรังสิต-นครนายก 57 ประชาธิปัตย์ ธัญบุรี ปทุมธานี` | นครนายก → `N` | ปทุมธานี / **ธัญบุรี** (ท่วม) |
| `ซอยบางนา-ตราด 36 บางนาใต้ บางนา กรุงเทพมหานคร` | ตราด → `N` | กทม. / **บางนา** (ท่วม) |
| `หมู่ที่ 7 สระแก้ว เมืองสุพรรณบุรี สุพรรณบุรี` | สระแก้ว → `N` | สุพรรณบุรี / **เมืองสุพรรณบุรี** (ท่วม) |
| `ถนนบางกรวย-ไทรน้อย บางกรวย บางกรวย นนทบุรี` | ไทรน้อย → ท่วม | นนทบุรี / บางกรวย (**ไม่ท่วม**) |

> ทั้งหมดนี้หายไปเองเมื่อ join ด้วยรหัสอำเภอ เพราะไม่ได้อ่านข้อความที่อยู่เลย

## บทเรียนโค้ดที่เจอในงานนี้

| เรื่อง | รายละเอียด |
|---|---|
| **อย่า join ทุกตารางใน query เดียวผ่าน linked server** | เขียนรวม `COLLECTION_S_ADDRESS` + `HP_COMMON_*` 6 ตารางในทีเดียว แล้ว**ค้างเกิน 10 นาที** (remote nested loop ทีละแถว) · ดึงแยกทีละตารางแล้ว join ใน pandas เสร็จใน ~2 นาที |
| **ห้าม `WITH (NOLOCK)`** | ตารางผ่าน linked server เป็น external table → error 46915 |
| **Python normalize ชื่อ keyword เป็น NFKC** | `dict(ค้างชำระ=...)` ทำให้ `ำ` (U+0E33) แตกเป็น `ํ` + `า` · หัวคอลัมน์ใน Excel ดูเหมือนเดิมแต่ **filter/ค้นหาไม่เจอ** → ต้องใช้ string literal เป็นคีย์ |
| **dict ค้นหาต้องใช้คีย์ tuple ทุกระดับ** | ระดับจังหวัดเป็น `str` แต่ค้นด้วย `prefix + (k,)` → ได้ **0%** โดยไม่มี error ดูเหมือนข้อมูลพัง |
| **นิยามต้องตรงกันทุกที่** | สรุปนับ `ค้างชำระ` จาก `OD_AMOUNT > 0` แต่ชีตรายละเอียดใช้ `เบี้ยปรับ > 0 หรือ ยอดค้าง > 0` → ต่างกัน 9 ราย (มีเบี้ยปรับแต่ `OD_AMOUNT` = 0) แก้ให้ใช้นิยามเดียว |
