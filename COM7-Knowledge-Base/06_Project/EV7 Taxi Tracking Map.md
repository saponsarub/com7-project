## Phase 0 · ทำความเข้าใจข้อมูล

**ถามเจ้าของระบบ GPS / ทีม EV7**
1. ฐานข้อมูลต้นทางคืออะไร (ชนิด DB · ชื่อตาราง) · ใครดูแล · ต่อตรงได้ไหม · ข้อมูลเข้าตารางถี่แค่ไหน
2. ความหมายของ `cm_engine` (0/1/2) · `cm_meter` · `cm_battery` · `header_center` · `signal_gps`
3. ทำไมทศนิยมพิกัดไม่เท่ากัน (2–5 ตำแหน่ง) — อุปกรณ์ต่างรุ่น? ตัดตอน export?
4. อุปกรณ์ส่งข้อมูลทุกกี่วินาทีจริง · ส่งตอนรถดับเครื่องไหม · ถ้าถอด GPS จะเห็นอะไรในข้อมูล (หยุดส่ง? ส่ง `V`?)
5. **ตัดสัญญาณรถ** ทำยังไง — มี immobilizer ไหม · คำสั่งสั่งจากไหน · ทำงานทันทีหรือรอรถดับเครื่อง
6. `car_id` / `vin` ผูกกับ**สัญญาเช่าซื้อ**ได้ไหม (ระบบไหน · คีย์อะไร) — จำเป็นสำหรับ Phase 4
7. ข้อมูลย้อนหลังเก็บไว้กี่วัน (ตอนนี้เห็นหนาแน่นแค่ 2 วัน)

**ถาม legal / DPO** — การติดตามตำแหน่งรถลูกหนี้: สัญญาให้ความยินยอมไว้ไหม · ใครดูได้ · เก็บนานเท่าไร → [[Consent & PDPA]]

## Phase 2 · รถอยู่บนถนนไหม

**ปัญหา:** พิกัดคลาด ±11 ม. (4 ตำแหน่ง) ถึง ±110 ม. (3 ตำแหน่ง) · ถนนในเมืองกว้าง 7–20 ม. → จุดรถมักไม่ตกบนเส้นถนนพอดี

**ข้อมูลถนน:** OpenStreetMap ประเทศไทย (Geofabrik `thailand-latest.osm.pbf` ~ หลักร้อย MB) · ใช้ `highway=*` เป็นเส้นถนน · `highway=traffic_signals` เป็นจุดสัญญาณไฟ · license ODbL (ต้องให้เครดิต OSM)

**ทำ 3 ขั้น จากง่ายไปยาก**

| ขั้น | วิธี | ได้อะไร |
|---|---|---|
| 2.1 ระยะถึงถนนที่ใกล้สุด | snap จุดไปเส้นถนนที่ใกล้ที่สุด (spatial index เช่น STRtree / H3) | `dist_to_road_m` · ชนิดถนน (มอเตอร์เวย์/ซอย) |
| 2.2 ความน่าจะเป็นที่อยู่บนถนน | logistic regression ด้วย feature: `dist_to_road_m` หารด้วยความคลาดตามทศนิยม · ความเร็ว · ทิศหัวรถเทียบทิศถนน · จุดก่อน-หลังอยู่ถนนเดียวกันไหม · อยู่ในพื้นที่ลานจอด/ปั๊ม (OSM `amenity=parking`/`fuel`/`charging_station`) | `p_on_road` 0–1 |
| 2.3 map matching ทั้งเส้นทาง | HMM map matching (เช่น OSRM / Valhalla `map_match` หรือไลบรารี Python) — ใช้ลำดับจุดตัดสินว่าวิ่งถนนไหน | เส้นทางที่รถน่าจะวิ่งจริง |

**label สำหรับ train 2.2** (ไม่มีคำตอบจริง) `[อนุมาน]`: จุดที่ `speed > 20` ถือว่า "บนถนน" · จุดที่จอดนาน > 2 ชม. ในลานจอด/อู่ ถือว่า "นอกถนน" → ตรวจด้วยตาบนแผนที่สักร้อยจุดก่อนเชื่อ

## Phase 3 · สถานะรถตอนนี้ — และ "ตัดสัญญาณแล้วอันตรายไหม"

**กฎ (ร่าง) จากข้อมูลจุดล่าสุด + ประวัติ 10–15 นาที**

| สถานะ | เงื่อนไข (ร่าง) |
|---|---|
| วิ่ง | `speed > 5` |
| ติดไฟแดง / รถติด | `speed = 0` นาน < 3 นาที · อยู่บนถนน (`p_on_road` สูง) · ใกล้ `traffic_signals` < 50 ม. หรือจุดก่อนหน้ากำลังวิ่ง |
| จอดริมถนน | `speed = 0` นาน > 5 นาที · บนถนน · ไม่ใกล้สัญญาณไฟ |
| จอดนอกถนน (ลานจอด/บ้าน/อู่) | `speed = 0` นาน > 5 นาที · `p_on_road` ต่ำ |
| ไม่มีข้อมูล | ไม่มีจุดใหม่เกิน X นาที → อาจดับเครื่อง/อับสัญญาณ/**ถอด GPS** |

**ความเสี่ยงถ้าตัดสัญญาณ (แสดงเป็นคำแนะนำ ไม่ใช่สั่งเอง)**
- 🟢 ต่ำ: จอดนอกถนน · ดับเครื่อง (`cm_engine` ต้องยืนยันความหมาย) · จอดนานพอ
- 🟡 กลาง: จอดริมถนน
- 🔴 สูง — **ห้ามตัด**: กำลังวิ่ง · ติดไฟแดง/รถติดบนถนน · บนทางด่วน/มอเตอร์เวย์ · ข้อมูลเก่าเกิน X นาที (ไม่รู้สถานะจริง)

⚠️ **การตัดสัญญาณต้องเป็นการตัดสินใจของคน** ตามนโยบายที่ legal/ฝ่ายติดตามหนี้กำหนด · ระบบให้แค่ข้อมูลประกอบ · พิกัดคลาดได้ร้อยเมตรในบางจุด → **สถานะ 🟢 ไม่ใช่การรับประกันความปลอดภัย** · ถ้าอุปกรณ์ตัดทันทีขณะวิ่ง ความเสี่ยงต่อชีวิตสูงมาก — ต้องยืนยันกลไกกับผู้ผลิต (Phase 0 ข้อ 5)

## Phase 4 · รถผิดสัญญา: จะไปไหน

**สถานการณ์:** ลูกหนี้ไม่จ่ายค่างวด อาจถอด GPS หรือขับออกต่างจังหวัด

| สิ่งที่ทำ | วิธี |
|---|---|
| จุดสุดท้ายที่รู้ + เวลา | จุดล่าสุดที่ `signal_gps = A` · บอกอายุข้อมูล |
| ทิศและความเร็วช่วงท้าย | เฉลี่ยทิศ (`direction` แบบ circular mean) และความเร็ว 5–10 จุดสุดท้าย → ลูกศรใหญ่บนแผนที่ |
| ระยะที่ไปได้ตั้งแต่ข้อมูลหาย | ความเร็วเฉลี่ย × เวลาที่หายไป → วง/กรวยความเป็นไปได้ตามทิศ (fan) · ใช้โครงข่ายถนนจำกัดพื้นที่ (Phase 2) |
| ปลายทางที่น่าจะไป | จากประวัติของคันนั้น: จุดจอดประจำ (บ้าน · อู่ · จุดรอผู้โดยสาร) ด้วยการจัดกลุ่ม (DBSCAN) → ให้คะแนนตามทิศที่มุ่งไป · ทางออกจังหวัดที่อยู่ในทิศนั้น |
| ออกนอกจังหวัด | เทียบจุดกับขอบเขต `D:\Master\geo` · แจ้งเมื่อข้ามจังหวัด |
| สัญญาณถอด GPS | ข้อมูลหายกลางทางขณะวิ่ง (ไม่ใช่หยุดตอนจอด) · ข้อมูลหายพร้อมกันกับตำแหน่งที่ไม่ใช่จุดอับสัญญาณประจำ `[อนุมาน — ต้องยืนยันว่าถอดแล้วข้อมูลเป็นแบบไหน]` |

**ข้อจำกัด:** ประวัติหนาแน่นมีแค่ 2 วัน → หาจุดประจำของแต่ละคันได้ไม่ดี · ต้องได้ข้อมูลย้อนหลังยาวกว่านี้ (Phase 0 ข้อ 7) หรือรอสะสมจากการต่อตรง
ต้องผูก `car_id` กับสัญญา/สถานะค้างชำระ (Phase 0 ข้อ 6) ถึงจะรู้ว่าคันไหน "ผิดสัญญา"

## Phase 6 · Realtime (ออกแบบไว้ ยังไม่สร้าง)

```
อุปกรณ์ GPS ─► DB ต้นทาง (EV7) ──CDC──► Stream ──► ประมวลผล ──┬─► hot store (ตำแหน่งล่าสุดต่อคัน) ─► API ─► แผนที่
                                     (MSK/Kafka                  │                                       ▲
                                      หรือ Kinesis)              └─► S3 Iceberg (ประวัติ · partition ตามวัน/คัน) ─► Athena / วิเคราะห์ Phase 2–5
```

| ส่วน | ทางเลือก | หมายเหตุ |
|---|---|---|
| ดึงจาก DB ต้นทาง | **CDC** (DMS · Debezium) หรือ polling ทุก N วินาทีตาม `created_at` | ถ้าเจ้าของ DB ไม่เปิด CDC → polling (เหมือนเรื่อง CDC ของ ITEC → [[Glue Jobs (ap-southeast-7)]]) |
| stream | **Amazon MSK (Kafka)** หรือ **Kinesis Data Streams** | Kinesis จัดการง่ายกว่า · MSK เหมาะถ้าองค์กรใช้ Kafka อยู่แล้ว `[อนุมาน — ต้องตรวจว่ามีใน ap-southeast-7]` |
| ประมวลผล | Managed Flink · หรือ Lambda ต่อ batch เล็ก | คำนวณสถานะ (Phase 3) · ข้ามจังหวัด · แจ้งเตือน |
| hot store | DynamoDB (key = vin) | ตำแหน่ง/สถานะล่าสุด ~4,000 คัน — เล็ก |
| ประวัติ | S3 Iceberg partition `date` + bucket(`car_id`) | ใช้ Glue/Athena เดิมของทีม |
| แสดงผล | API (API Gateway + Lambda) → เว็บดึงทีละคัน · ทั้งฝูงใช้ vector tile / H3 | ไม่ส่งข้อมูลทั้งหมดไปหน้าเว็บ |

**ประมาณขนาดข้อมูล** (สมมติ ~4,000 คัน ส่งทุก 4 นาที ตลอด 24 ชม.): ~1.4 ล้านจุด/วัน · ~530 ล้านจุด/ปี · ~100 byte/จุด → ~53 GB/ปี ก่อนบีบอัด → **ไม่ใหญ่สำหรับ S3/Iceberg** · ถ้าความถี่เพิ่มเป็นทุก 10 วินาที → ~1.3 หมื่นล้านจุด/ปี จึงต้องออกแบบ partition/tile ตั้งแต่ต้น `[อนุมาน — ขึ้นกับความถี่จริงจาก Phase 0]`
