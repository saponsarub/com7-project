## 🔴 บทเรียนที่ใหญ่ที่สุด — คลังกลางไม่ได้ "ขาย" แต่ "โอน"

รอบแรกผมนับ outbound เป็น `Sales` / `Sales order` ตามตัวอักษรของโจทย์ ได้ผลผิดชัดเจน

```
COM7 คลัง 4   รับเข้า 15.3 ล้านชิ้น   จ่ายออก 0.9 ล้าน   ← ต่างกัน 17 เท่า
```

ตรวจแล้วพบว่า

| ITEC สาขา | `Transfer-Out` | `Sales` |
|---|--:|--:|
| `4` (คลังกลาง) | **8,424,259 แถว** | **0 แถว** |
| `77` (online) | 84,912 | 879,824 |

**คลังกลางส่งของออกด้วยการโอนไปสาขา ไม่ใช่การขาย** ฝั่ง FO ก็เหมือนกัน

จึงเพิ่มคอลัมน์ **`MovementType`** แยก 3 ประเภท

| ค่า | หมายถึง |
|---|---|
| `PO ซื้อเข้า` | ซื้อจากผู้ขาย (refcat 3 · ITEC `Buy (Local)` `Buy (Oversea)` `Consign`) |
| `SO ขาย` | ขายให้ลูกค้าโดยตรง (refcat 0 · ITEC `Sales` `Return Sales`) |
| `Transfer โอน` | โอนระหว่างคลัง/สาขา (refcat 6 · 21 · 22 · ITEC `Transfer-In/Out`) |

**ถ้านับแค่ PO + SO ของที่ผ่านคลังจะหายไปเกือบ 90%**

## 🔴 หมวดสินค้าเป็นคนละชุด — แก้ด้วยสะพานรหัส

COM7 ปี 2025 มาจาก ITEC (หมวดชุดหนึ่ง) ปี 2026 มาจาก FO (อีกชุด) เทียบข้ามปีไม่ได้

**ทางออก** — เติมหมวด**ทั้งสองชุด**ให้ทุกแถว ไม่ว่าข้อมูลมาจากระบบไหน

```
Transaction_FO  ->  DISTINCT ([ITEC-ITEMNO], [FO-ITEMNO], CompanyCode)
                    93,468 คู่รหัส  ผูกกัน 1:1 ภายในบริษัทเดียวกัน
```

แถวจาก ITEC ได้รหัส FO มาเติม · แถวจาก FO ได้รหัส ITEC อยู่แล้ว → **ทุกแถวมีครบทั้ง 5 คอลัมน์หมวด**

| คอลัมน์ | มาจาก |
|---|---|
| `ITEC_Category` · `ITEC_SubCategory` | `rpt.dim_item_itec` |
| `FO_GroupCategory` · `FO_CategoryName` · `FO_SubCategoryName` | `tm_Item` → `tm_FinDimValueSet` |

ความครบถ้วน — หมวด FO ว่าง 7 จาก 124,398 แถว · หมวด ITEC ว่าง 2,794 (2.2%)

⚠️ หมวดฝั่ง FO ไม่ใช่ลำดับชั้นจริง **345 จาก 487 หมวดชี้ไปหลายกลุ่ม** และ com7 จัดสินค้า demo ทุกชนิดไว้ใต้กลุ่ม `iPhone` → [[D365 F&O - Query Cookbook]]

## 🔴 Product Master — ขนาด/น้ำหนักไม่มีข้อมูลเลย

โจทย์ขอ "Dimension, Weight เท่าที่มีทั้ง ITEC และ D365FO" — คำตอบคือ **ไม่มีทั้งคู่**

| ระบบ | สภาพ |
|---|---|
| ITEC `rpt.dim_item_itec` | **ไม่มีคอลัมน์** — มีแค่ ItemId · ItemName · Category · SubCategory · Model/Series · Brand |
| D365FO `inventtable` | **มีคอลัมน์แต่ว่างเปล่า** |

ตรวจครบทุกบริษัท 360,823 แถว

| คอลัมน์ | แถวที่ไม่เป็นศูนย์ |
|---|--:|
| `width` `height` `depth` | **0** |
| `netweight` `taraweight` | **0** |
| `grosswidth` | 1 (gi) |
| `unitvolume` | 1 (drph) |

ยังคงคอลัมน์ไว้ในชีต 5 เพื่อให้เห็นว่าฟิลด์มีอยู่จริงแต่ไม่มีใครกรอก
ชีต 5 จึงมีประโยชน์ในฐานะ **ตารางแปลงรหัส ITEC ↔ FO + หมวด + แบรนด์** (183,357 แถว)

> ถ้าที่ปรึกษาต้องการขนาด/น้ำหนักจริง ต้องเก็บใหม่ หรือขอจากผู้ผลิต

## Monthly Stock Snapshot — วิธีคำนวณ

**COM7 ปี 2025** ใช้ `rpt.onhandendmonth_itec` ตรง ๆ (ตัวเลขที่ระบบบันทึกไว้จริง)
⚠️ view นี้มีถึง **2026-06-01 เท่านั้น** จึงใช้ได้เฉพาะปี 2025 ตามที่โจทย์กำหนดอยู่แล้ว

**ที่เหลือ** ฝั่ง FO ไม่มีตารางสำเร็จ จึง**ไล่สะสม** เอง

```sql
SELECT BU, Warehouse, ItemId,
       CASE WHEN DATEPHYSICAL < '2025-01-01' THEN '2024-12'
            ELSE CONVERT(varchar(7), DATEPHYSICAL, 120) END AS YearMonth,
       SUM(QTY)
FROM Transaction_FO
WHERE DATEPHYSICAL < '2026-09-01' AND REFERENCECATEGORY <> 7
GROUP BY ...
```

แล้ว `cumsum()` ต่อ (BU, คลัง, สินค้า) — ยอดก่อนปี 2025 ยุบเป็นก้อน `2024-12` = ยอดยกมา
ตัด `REFERENCECATEGORY = 7` (Weighted average inventory closing) ออกเพราะไม่ใช่การเคลื่อนไหวจริง
