## แนวคิดหลัก

**โค้ดหาตัวเลข · LLM แค่เรียบเรียงภาษา** — ไม่ให้ LLM คิดเลขหรือจำข้อมูลเอง จึงไม่แต่งตัวเลข

```
คำถาม ─► ① ดึงค่า (ส่วน 3)        ทะเบียน · สถานที่ (ทนพิมพ์ผิด) · เวลา
       ─► ② เลือกประเภท (ส่วน 5 / 7.2)  classifier 8 ประเภท + semantic router 8 แบบวิเคราะห์
       ─► ③ คำนวณจากข้อมูลจริง (ส่วน 6 / 7.2)  pandas บน points.parquet
       ─► ④ เรียบเรียงคำตอบ   template (7) · Qwen (10) · Claude (11)
```

ตอบผิด → ดูว่าผิดที่ชั้นไหน: `chat(q, show_facts=True)` แสดงข้อเท็จจริงที่ ③ หามาให้
- ข้อเท็จจริงถูก แต่พูดไม่ดี → แก้ชั้น ④ (`FEWSHOT` / รุ่น Qwen)
- ข้อเท็จจริงผิด/ผิดประเภท → แก้ชั้น ② (`EXAMPLES` ใน 7.2) หรือเพิ่มตัวคำนวณใน ③
- ระบบตอบได้**เฉพาะคำถามที่มีตัวคำนวณรองรับ** — เทรนให้เก่งขึ้นอย่างเดียวไม่ช่วยเรื่องนี้

## ส่วน 1 · โหลดข้อมูล → ตาราง `pos`

- อ่าน `points.parquet` + เติมชื่อเขต/จังหวัดจาก `dist_pip.geojson` (คอลัมน์ `dist` = ลำดับ feature)
- คำนวณ `status` ต่อจุด: `signal = V` → ไม่มีสัญญาณ · `meter = F` → มีผู้โดยสาร · ความเร็ว ≥ 5 กม./ชม. → ว่าง·วิ่ง · อื่น ๆ → จอด
- `LATEST` = เวลาล่าสุดของข้อมูล (1 ต.ค. 15:29) — **"ตอนนี้" ในระบบ = เวลานี้ ไม่ใช่เวลาจริง**

## ส่วน 2 · รายชื่อสถานที่ (gazetteer)

- รวมชื่อจังหวัด/อำเภอ/เขต ไทย + อังกฤษ + คำนำหน้า ("จังหวัด", "อำเภอ", "เขต" — "เขต" ใช้กับกรุงเทพฯ เท่านั้น)
- ชื่อเล่น `ALIAS`: กทม / กรุงเทพ / บางกอก / bkk → กรุงเทพฯ · โคราช → นครราชสีมา · อยุธยา
- `cent` = จุดกึ่งกลางจังหวัด ใช้หาสถานีชาร์จใกล้จังหวัด

## ส่วน 3 · ดึงค่าจากคำถาม (slot)

| ฟังก์ชัน | ดึงอะไร | วิธี |
|---|---|---|
| `find_plate` | ทะเบียน / EV-xxxx | regex |
| `find_time` | "ล่าสุด" · "วันนี้" · "เมื่อวาน" · "14:30" · "9 โมง" | กฎ |
| `find_place` | สถานที่ ทนพิมพ์ผิด ("ภูเกต" → ภูเก็ต) | difflib fuzzy + กรองด้วย bigram ก่อน (เร็วขึ้น) |
| `extract` | รวมทั้งสาม | |

กันจับผิด: fuzzy ใช้กับชื่อ ≥ 4 ตัวอักษร · คะแนนขั้นต่ำ **0.85** (ต่ำกว่านี้ "ดาวอังคาร" กลายเป็น "นาวัง" · "สนม" / "ลี้" จับผิดง่าย)

## ส่วน 4 · สร้างชุดข้อมูลสอน

- แม่แบบคำถาม `T` 8 ประเภท: `cars_in_area` · `car_status` · `car_track` · `out_of_zone` · `fleet_stats` · `nearest_charger` · `action_request` (สั่งการรถ — ปฏิเสธ) · `other` (นอกเรื่อง)
- เติมสถานที่/ทะเบียน/เวลาสุ่ม + คำพิมพ์ผิด (`typo`) + คำขึ้นต้น/ลงท้าย ("ขอ", "ครับ", "ด่วน") แม่แบบละ 25 ประโยค
- `mask()` แทนค่าที่ดึงได้ด้วยคำกลาง ("สถานที่", "ทะเบียนรถ") ก่อนเข้า classifier → ไม่จำชื่อจังหวัดแทนรูปประโยค
- ⚠️ ชุดนี้**แต่งเอง** — คำถามที่คนพิมพ์จริงอาจหน้าตาต่าง · วิธีทำให้เก่งขึ้นที่คุ้มสุด = เก็บคำถามจริงมาเพิ่ม

## ส่วน 5 · เทรนตัวจัดประเภทคำถาม

- **Backbone** `paraphrase-multilingual-MiniLM-L12-v2` (ตัวเดียวกับโมเดลจัดหมวดสินค้า ITEC) แปลงประโยค → เวกเตอร์ · ประโยคความหมายคล้ายกันได้เวกเตอร์ใกล้กัน แม้ใช้คำต่างกัน
- **Classifier** LogisticRegression บนเวกเตอร์ → ทายประเภท · เทรนไม่กี่วินาที ไม่ต้องใช้ GPU
- แบ่ง train/test ด้วย **GroupShuffleSplit ตามแม่แบบ** (ประโยคจากแม่แบบเดียวกันไม่อยู่ทั้งสองฝั่ง → วัดผลไม่หลอกตัวเอง) + ชุดทดสอบที่เขียนเอง
- บันทึก `qa_intent.joblib`

## ส่วน 7 · `ask()` + template

- ต่อ 3 → 5 → 6 → `answer()` (template) · มั่นใจต่ำกว่า `MIN_CONF = 0.45` → ถามกลับ ไม่เดา

## 7.1 · จัดอันดับพื้นที่

- "เขต/อำเภอ/จังหวัดไหนมีรถมากที่สุด" (regex `RANK_RE`) · ใส่จังหวัด → อันดับเขต/อำเภอในจังหวัด · ไม่ใส่ → อันดับจังหวัดทั้งประเทศ
- เพิ่มเพราะเดิมระบบตอบยอดรวมกรุงเทพฯ แทนการจัดอันดับเขต

## 7.2 · คำถามเชิงวิเคราะห์ (เพิ่ม 2026-10-16)

| แบบ | ฟังก์ชัน | คำนวณยังไง |
|---|---|---|
| ช่วงผู้โดยสารเยอะ | `x_peak_hour` | นับรถมีผู้โดยสาร (ไม่ซ้ำ) ต่อชั่วโมง เฉลี่ยตามชั่วโมงของวัน · พูดแบบไทย (`th_hour`: 15 → "บ่าย 3") |
| ช่วงวันที่ของข้อมูล | `x_data_range` | min/max ของ `gps_time` |
| จำนวนสถานีชาร์จในพื้นที่ | `x_chargers_in_area` | ระบุเขตของสถานีด้วย point-in-polygon (shapely STRtree) |
| รถจอดใกล้สถานีชาร์จ | `x_cars_near_chargers` | รถสถานะจอด ห่างสถานี ≤ 300 ม. (`NEAR_KM`) — ไม่รู้ว่าชาร์จจริงไหม |
| แนะนำทำเลเปิดสถานีชาร์จ | `x_site_recommend` | คะแนน = รถเฉลี่ยต่อชั่วโมงในเขต ÷ (สถานีที่มี + 1) · ไม่ระบุจังหวัด = กรุงเทพฯ |
| เดาปลายทางรถที่สัญญาณหาย | `x_lost_signal` | รถที่จุดล่าสุดเก่า > 15 นาที และกำลังวิ่ง ≥ 20 กม./ชม. → ต่อเส้นตามทิศ × ความเร็ว × เวลาที่หาย (ไม่เกิน 150 กม.) → เขตที่ตกลง · **คาดเดา ไม่ใช่ตำแหน่งจริง** |
| รถรับผู้โดยสารบ่อยสุด | `x_top_trips` | นับครั้งที่มิเตอร์เปลี่ยน E → F + รวมเวลาที่เป็น F |
| สัดส่วนรถวิ่ง/จอด | `x_status_ratio` | % ตามสถานะ + อัตราส่วนแบบรวมเป็น 100 (`ratio`) |

**Semantic router (`route_analytic`):**
1. แปลงคำถาม (ผ่าน `mask`) เป็นเวกเตอร์ด้วย MiniLM ตัวเดิม
2. เทียบกับตัวอย่างใน `EXAMPLES` และกับคำถามแบบเดิมจากส่วน 4
3. ใช้ตัวคำนวณใหม่เมื่อ ① คะแนน ≥ `ROUTE_MIN` (0.72) ② ใกล้กว่าคำถามแบบเดิม ③ ไม่ใช่กลุ่ม `_pass` (คำถามที่หน้าตาคล้ายแต่ส่วน 6 ตอบอยู่แล้ว)
4. **ไม่ต้องเทรน** — เข้าใจผิด = เพิ่มประโยคนั้นใน `EXAMPLES` แล้วรัน 7.2 → 10 ใหม่ · ดูการตัดสินใจ: `ask(q, verbose=True)`

## ส่วน 8 · LoRA (พักไว้)

- สอน **Qwen2.5-1.5B-Instruct** (4-bit) ให้อ่านคำถามแล้วตอบเป็น JSON `{"intent", "place"}` ใช้แทนส่วน 5
- **LoRA** = ไม่แก้น้ำหนักเดิม 1,500 ล้านตัว แต่แปะชั้นเล็ก (~1%) แล้วเทรนเฉพาะชั้นนั้น → เทรนบน T4 ฟรีได้ · ไฟล์ adapter หลักสิบ MB
- 8.1 เปิด `RUN_LLM = True` · 8.2 ชุดสอน (คำถาม → JSON) · 8.3 ติดตั้ง peft/bitsandbytes · 8.4–8.7 โหลด+เทรน · 8.8 ทดสอบ · 8.9 บันทึก · **8.9b โหลดตัวที่เทรนไว้ (ข้าม 8.4–8.7)** · 8.10 `ask_llm()` · 8.11 `ลองถาม()`
- ผลทดสอบชุด 20 ข้อ (ตอนเทรน): LLM 100% vs classifier 95% แต่**ใช้จริงแย่**:
  - คำตอบออกมาจาก template (LoRA ทำแค่ JSON) → แข็งเหมือนเดิม
  - เทรนจากแม่แบบที่แต่งเอง 1 epoch → จำรูปประโยค (overfit) · ชุดทดสอบหน้าตาคล้ายชุดสอนเลยได้ 100%
  - โมเดลเล็ก (1.5B 4-bit) · ไม่รู้จักประเภทที่เพิ่มทีหลัง (7.1 · 7.2)
- จะกลับมาใช้เมื่อมีคำถามจริงจำนวนมากพอเทรน

- **Qwen2.5-3B-Instruct สำเร็จรูป ไม่ได้เทรน** ทำหน้าที่เรียบเรียงข้อเท็จจริงเป็นภาษาพูด
- `facts_for(q)` → 7.2 ก่อน (ถ้าใช่คำถามวิเคราะห์) → 7.1 → ส่วน 5 + 6
- `SYSTEM` = กติกา: ตอบเฉพาะที่ถาม 1–2 ประโยค · ห้ามเพิ่มตัวเลข/ชื่อ/ทะเบียนที่ไม่มีในข้อมูล · ใช้คำแบบคนไทยถ้ามีในข้อมูล · บอกเมื่อเป็นการประมาณ
- `FEWSHOT` = ตัวอย่าง 3 คู่ (ข้อเท็จจริง → คำตอบที่อยากได้) ให้ Qwen เลียนแบบความยาวและน้ำเสียง
- `memory` จำรถ/สถานที่ล่าสุด → เข้าใจ "คันนี้", "ที่นั่น"
- **ตัวกันตัวเลข `safe()`:** ทุกกลุ่มตัวเลขในคำตอบต้องมีในข้อเท็จจริง ไม่งั้นใช้คำตอบจากระบบแทน · ⚠️ เทียบทีละกลุ่มตัวเลข จึงหลุดได้ (ทดสอบ: "3 ต.ค." ผ่านเพราะมี "3,649" ในข้อเท็จจริง)
- เปลี่ยนรุ่น: `CHAT_LLM = "Qwen/Qwen2.5-7B-Instruct"` (โหลด 4-bit อัตโนมัติ ~5 GB · ครั้งแรกดาวน์โหลด ~15 GB) · ต้อง `del cmodel; torch.cuda.empty_cache()` ก่อนรันใหม่ · ระวังพิมพ์ชื่อผิด (`Qwen2.57B` → OSError)
- ใช้: `chat("คำถาม", show_facts=True)` · คุยต่อเนื่อง `แชต()` (Enter ว่าง = จบ · "ล้าง" = เริ่มใหม่)
