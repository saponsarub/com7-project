## 1. ข้อสรุปสำคัญก่อนออกแบบ

### คำถามแบบนี้ไม่ใช่งาน RAG
RAG (ค้นเอกสารด้วย embedding แล้วให้ LLM อ่าน) เหมาะกับ **ข้อความ** เช่น คู่มือ นโยบาย
คำถาม "รถคันไหนอยู่ภูเก็ตตอนนี้" เป็นการ **query ข้อมูลตาราง** (พิกัด 1.17 ล้านจุด) — ต้องนับ/กรองให้ถูกทุกแถว embedding ทำไม่ได้
→ ใช้ **LLM + tool use (function calling)**: LLM แปลงคำถามเป็นการเรียกฟังก์ชันที่เราเขียนไว้ ฟังก์ชันไป query ข้อมูลจริง แล้ว LLM สรุปผลเป็นภาษาไทย

RAG ยังใช้ได้กับส่วนเล็ก ๆ: นิยามคำ ("รถนอกเขต" คืออะไร) · คำอธิบายคอลัมน์ · ตัวอย่างคำถาม-คำตอบ

### โมเดลจากโปรเจกต์ ITEC category ใช้ตรงไหนได้
โมเดลนั้น (`scripts/itec/category`, `finetune`) = **sentence-transformer** (multilingual MiniLM / e5 / bge-m3) แปลงข้อความเป็นเวกเตอร์ + **LinearSVC** จัดหมวด → **ไม่ใช่ LLM** ตอบคำถาม/สรุปผลเป็นภาษาไม่ได้ แต่ยกมาใช้ได้ 2 ส่วน:

| ส่วนของโมเดลเดิม                      | ใช้ในระบบนี้ทำอะไร                                                                                                                                                                                                                        |
| ------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ตัวแปลงข้อความเป็นเวกเตอร์ (embedder) | **จับคู่ชื่อสถานที่ที่พิมพ์ผิด/ย่อ** เช่น "ภูเกต" "ภูเก็จ" "Phuket" → จังหวัดภูเก็ต (เทียบกับชื่อจังหวัด/อำเภอใน `D:\Master`) · ค้นตัวอย่างคำถามที่คล้ายกันมาใส่ prompt                                                                   |
| ตัวจัดหมวด (LinearSVC)                | เทรนใหม่เป็น **ตัวจัดประเภทคำถาม (intent router)** เช่น `หารถในพื้นที่` · `ตำแหน่งรถคันเดียว` · `เส้นทาง` · `นอกเขต` · `สถิติ` · `อื่น ๆ` → คำถามที่ชัดเจนตอบได้โดยไม่ต้องเรียก LLM (เร็ว ฟรี ข้อมูลไม่ออกนอกองค์กร) · ที่เหลือส่งให้ LLM |

ต้องมีตัวอย่างคำถามจริงที่ติดป้ายแล้วอย่างน้อยหลักร้อยข้อต่อหมวดก่อนจะเทรน router ได้ `[อนุมาน — ตามขนาดข้อมูลที่โมเดล ITEC ใช้]`

## 2. สถาปัตยกรรม

```
หน้าแผนที่ (แชต)
   │ คำถามภาษาไทย
   ▼
API (FastAPI บน EC2 / Lambda)
   ├─① intent router (โมเดล ITEC เทรนใหม่) ── คำถามง่าย ──► เรียก tool ตรง ──┐
   └─② Claude (tool use) ── เลือก tool + ใส่ค่า ──► tools ───────────────────┤
                                                                          ▼
                                                   ชั้น query (อ่านอย่างเดียว)
                                                   ตอนนี้: DuckDB อ่าน points_clean.parquet
                                                   อนาคต: Athena/Iceberg (ประวัติ) + DynamoDB (ตำแหน่งล่าสุด realtime)
   ◄── คำตอบภาษาไทย + รายการ car_id ──────────────────────────────────────────┘
   ▼
หน้าเว็บ: แสดงคำตอบ · ไฮไลต์รถบนแผนที่ · ตารางผลลัพธ์ (แสดงทะเบียนจากฝั่งเว็บ)
```

## 3. Tools (ฟังก์ชันที่ LLM เรียกได้)

ทุกตัว **อ่านอย่างเดียว** · จำกัดจำนวนแถวที่คืน · คืน `car_id` ไม่คืนทะเบียน/VIN (ดูข้อ 5)

| tool | รับ | คืน | ตัวอย่างคำถาม |
|---|---|---|---|
| `resolve_place` | ข้อความชื่อสถานที่ | รหัส + ชื่อเต็ม จังหวัด/อำเภอที่ตรงที่สุด (ใช้ embedder ของ ITEC + ชื่อใน `D:\Master`) | (เรียกก่อน tool อื่นเสมอเมื่อมีชื่อสถานที่) |
| `cars_in_area` | `area_code` · `at_time` (ว่าง = เวลาล่าสุดของข้อมูล) · `status` | จำนวน + รายการ car_id + สถานะ | "ตอนนี้รถคันไหนอยู่ภูเก็ตบ้าง" |
| `car_status` | `car_id` หรือทะเบียน · `at_time` | ตำแหน่ง · สถานะ · ทิศ · ความเร็ว · อายุข้อมูล · จังหวัด/อำเภอ | "ทอ-4141 อยู่ไหน" |
| `car_track` | `car_id` · `from` · `to` | สรุปเส้นทาง: ระยะทาง · จังหวัดที่ผ่าน · จุดจอดนาน | "เมื่อวาน ทอ-4141 ไปไหนมาบ้าง" |
| `cars_out_of_zone` | `zone` · `from` · `to` | รถที่ออกนอกเขต + ช่วงเวลา | "วันนี้มีรถออกนอกเขต กทม. กี่คัน" |
| `fleet_stats` | `metric` (จำนวนรถ · ชม.วิ่ง · ชม.มีผู้โดยสาร) · `group_by` (จังหวัด/อำเภอ/ชั่วโมง) · ช่วงเวลา | ตารางสรุป | "จังหวัดไหนมีรถวิ่งเยอะสุด" |
| `nearest_chargers` | `lat` · `lon` หรือ `car_id` · `k` | สถานีชาร์จใกล้สุด k แห่ง + ระยะ | "รถคันนี้ใกล้จุดชาร์จไหน" |

**ทำไมไม่ให้ LLM เขียน SQL เอง (text-to-SQL) ตั้งแต่แรก:** tool ที่กำหนดไว้ควบคุมได้ว่าดึงอะไรได้บ้าง · ตรวจผลง่าย · ไม่มีความเสี่ยงที่ SQL ผิด/ช้า/ดึงข้อมูลเกินสิทธิ์ · ถ้าคำถามหลากหลายเกิน tool ที่มี ค่อยเพิ่ม `run_sql` แบบจำกัด (view ที่อนุญาตเท่านั้น · login อ่านอย่างเดียว · `LIMIT` บังคับ · timeout)

## 4. โมเดลและค่าใช้จ่าย

|                                        | ค่า                                                                                                                                       |
| -------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| โมเดลหลัก                              | **Claude Opus 5.5** (`claude-opus-5-5`) · $4 / $20 ต่อ 1 ล้าน token (input / output)                                                      |
| ทางเลือกถูกกว่า (ถ้าทดสอบแล้วคุณภาพพอ) | Claude Haiku 5.5 (`claude-haiku-5-5`) · $0.10 / $0.50                                                                                     |
| ตั้งค่า                                | `output_config.effort = "low"` สำหรับคำถามสั้น ๆ (Opus 5.5 ค่าเริ่มต้นคือ `medium`) · cache ส่วน system prompt + tools                    |
| ประมาณต่อคำถาม (Opus 5.5)              | input ~5,000 token (prompt + tools + ผล tool) + output ~600 → ~$0.03 (≈ 1 บาท) · ถ้า cache ส่วนคงที่ได้ ถูกลงอีก `[อนุมาน — ต้องวัดจริง]` |
| 1,000 คำถาม/เดือน                      | ~$30 (≈ 1,000 บาท) · คำถามที่ router ตอบเองไม่เสียค่า LLM                                                                                 |

ตัวเลือกช่องทางเรียก: Claude API ตรง · Claude Platform on AWS (บิลผ่าน AWS) · Amazon Bedrock — **ต้องตรวจว่ามีโมเดลใน ap-southeast-7 หรือไม่** และข้อมูลจะถูกประมวลผลประเทศไหน (Claude API ตั้ง `inference_geo` ได้แค่ `us` / `global`)

## 5. ความปลอดภัย / PDPA

| ความเสี่ยง | วิธีลด |
|---|---|
| ตำแหน่งรถ + ทะเบียน = ข้อมูลส่วนบุคคล ส่งออกนอกประเทศไปที่ LLM | ส่งให้ LLM แค่ **car_id** · หน้าเว็บแปลง car_id → ทะเบียนเอง · ส่งเฉพาะผลสรุปที่ต้องใช้ · **ขออนุมัติ DPO ก่อนใช้กับข้อมูลจริง** → [[Consent & PDPA]] |
| LLM แต่งคำตอบ | system prompt: ตอบจากผล tool เท่านั้น · ไม่มีผลให้บอกว่าไม่รู้ · แสดงตาราง/จุดบนแผนที่ประกอบทุกคำตอบ ให้ผู้ใช้ตรวจได้ |
| "ตอนนี้" ไม่ใช่ตอนนี้จริง | ข้อมูลยังเป็น batch → ทุกคำตอบต้องบอก "ข้อมูล ณ เวลา …" |
| ผู้ใช้ถามเกินสิทธิ์ | tools อ่านอย่างเดียว · ใช้สิทธิ์ตามผู้ใช้ที่ login · เก็บ log คำถาม/tool ที่เรียก |
| การตัดสัญญาณรถ | **ไม่มี tool ที่สั่งการรถได้** — ระบบนี้ตอบคำถามเท่านั้น |

## 6. ตัวอย่างโค้ด (ร่าง · ยังไม่ได้รัน)

ใช้ Anthropic Python SDK + tool runner (`pip install anthropic duckdb`) · key อ่านจาก env `ANTHROPIC_API_KEY` ห้ามเขียนในโค้ด

```python
import anthropic, duckdb
from anthropic import beta_tool

con = duckdb.connect()
con.execute("CREATE VIEW positions AS SELECT * FROM 'scripts/taxi/_out/positions.parquet'")   # view ที่เตรียมตามข้อ 2

@beta_tool
def resolve_place(text: str) -> str:
    """แปลงชื่อสถานที่ที่ผู้ใช้พิมพ์ (อาจสะกดผิด) เป็นรหัสจังหวัด/อำเภอ ต้องเรียกก่อน tool อื่นเมื่อคำถามมีชื่อสถานที่

    Args:
        text: ชื่อสถานที่ตามที่ผู้ใช้พิมพ์ เช่น "ภูเกต"
    """
    ...  # embedder ของ ITEC เทียบกับชื่อใน D:\Master → คืน JSON {"province_code": "83", "name": "ภูเก็ต", "score": 0.93}

@beta_tool
def cars_in_area(province_code: str, at_time: str = "") -> str:
    """รายการรถที่อยู่ในจังหวัดนี้ ณ เวลาที่ระบุ (ว่าง = เวลาล่าสุดของข้อมูล) คืน car_id ไม่คืนทะเบียน

    Args:
        province_code: รหัสจังหวัด 2 หลักจาก resolve_place
        at_time: เวลา ISO เช่น 2026-10-01T09:00 หรือว่าง
    """
    t = at_time or con.execute("SELECT max(gps_time) FROM positions").fetchone()[0]
    rows = con.execute("""
        SELECT car_id, status, gps_time FROM (
          SELECT *, row_number() OVER (PARTITION BY car_id ORDER BY gps_time DESC) rn
          FROM positions WHERE gps_time <= CAST(? AS TIMESTAMP) AND gps_time > CAST(? AS TIMESTAMP) - INTERVAL 15 MINUTE)
        WHERE rn = 1 AND province_code = ? LIMIT 200""", [t, t, province_code]).fetchall()
    return f'{{"as_of": "{t}", "count": {len(rows)}, "cars": {[r[0] for r in rows]}}}'

client = anthropic.Anthropic()
SYSTEM = ("คุณคือผู้ช่วยตอบคำถามเรื่องรถแท็กซี่ EV7 ตอบเป็นภาษาไทย "
          "ตอบจากผลของ tool เท่านั้น ถ้าไม่มีข้อมูลให้บอกว่าไม่ทราบ ห้ามเดา "
          "ทุกคำตอบต้องบอกเวลาของข้อมูล (as_of) และอ้างรถด้วย car_id")

runner = client.beta.messages.tool_runner(
    model="claude-opus-5-5",
    max_tokens=16000,
    system=SYSTEM,
    output_config={"effort": "low"},
    tools=[resolve_place, cars_in_area],
    messages=[{"role": "user", "content": "ตอนนี้รถคันไหนอยู่ภูเกตบ้าง"}],
)
for message in runner:
    final = message
print(next(b.text for b in final.content if b.type == "text"))
```

ตรวจ `stop_reason` ก่อนอ่านคำตอบเสมอ (`refusal` = โมเดลปฏิเสธ) · ใส่ fallback ฝั่ง server เมื่อทำเป็นระบบจริง
