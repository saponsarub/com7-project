# ดัชนีและการเขียนคิวรีให้เร็ว

ตารางนี้ **ไม่มี clustered index** มีแต่ nonclustered 2 ตัว

| ชื่อ | คอลัมน์เรียงตามลำดับ |
|---|---|
| `ix0` | `INVENTSERIALID` → `ITEC-ITEMNO` → `INVENTLOCATIONID` → `CompanyCode` → `DATEPHYSICAL` |
| `ix1` | `FO-ITEMNO` → `CompanyCode` |

**เขียน `WHERE` ให้เริ่มจากคอลัมน์ซ้ายสุดของดัชนี**

```sql
-- ✅ ใช้ ix1 ได้
WHERE [FO-ITEMNO] = '0000157849' AND CompanyCode = 'com7'

-- ✅ ใช้ ix0 ได้
WHERE INVENTSERIALID = '359...' AND [ITEC-ITEMNO] = '8851...'

-- ❌ ไม่มีดัชนีช่วย ต้องสแกนทั้ง 276 ล้านแถว
WHERE CompanyCode = 'com7' AND DATEPHYSICAL >= '2026-01-01'
```

เวลาที่วัดได้จริงจากการสำรวจครั้งนี้

| งาน | เวลา |
|---|---|
| `GROUP BY REFERENCECATEGORY, Transaction_Type` ทั้งตาราง | 16 วิ |
| `GROUP BY CompanyCode` ทั้งตาราง | 48 วิ |
| นับค่าว่าง 14 คอลัมน์พร้อมกัน | 32 วิ |
| `COUNT(DISTINCT)` 4 คอลัมน์ | 69 วิ |
| `GROUP BY LEN([FO-ITEMNO])` | 77 วิ |
| join `tm_Warehouse` ข้ามฐาน ทั้ง 276M แถว | 28 วิ |

ใส่ `WITH (NOLOCK)` เสมอ — เป็นฐาน production ของคนอื่น

# สูตรสำเร็จ

### นับยอดขายให้ถูก

```sql
SELECT CompanyCode, SUM(-QTY) AS ขายสุทธิ, SUM(-RealCost) AS ต้นทุนขาย
FROM PROJECT_1.dbo.Transaction_FO WITH (NOLOCK)
WHERE REFERENCECATEGORY = 0                    -- Sales order
  AND DATEPHYSICAL >= '2026-01-01'
  AND DATEFINANCIAL >= '1901-01-01'            -- ตัดที่ยังไม่ลงบัญชี
GROUP BY CompanyCode
```

QTY ของการขายเป็นลบ จึงใส่ `-` เพื่อให้ได้จำนวนบวก · ยอดบวกที่ปนมา 145,047 แถวคือการรับคืน ซึ่งหักออกให้เองอัตโนมัติ

### ความเคลื่อนไหวสต็อกที่เป็นของจริง

```sql
WHERE REFERENCECATEGORY <> 7     -- ตัด Weighted average inventory closing
  AND DATEPHYSICAL >= '2020-01-01'
```

### รายการที่มี serial ใช้ได้จริง

```sql
WHERE INVENTSERIALID IS NOT NULL
  AND INVENTSERIALID <> 'NULL'
  AND INVENTSERIALID <> 'PENDING'
  AND LEN(INVENTSERIALID) >= 8
```

### การโอน — ต้องแยกตาม BU

```sql
-- com7
WHERE CompanyCode = 'com7' AND REFERENCECATEGORY = 6

-- BU อื่น (4 ขา ผ่านคลังพัก)
WHERE CompanyCode <> 'com7' AND REFERENCECATEGORY IN (21, 22)
```

### ต่อชื่อคลัง

```sql
FROM PROJECT_1.dbo.Transaction_FO t WITH (NOLOCK)

       ON w.SysCompanyId = t.CompanyCode
```

# สรุปกฎ 10 ข้อที่ห้ามลืม

1. `WHERE DATEPHYSICAL >= '2020-01-01'` — ก่อนนั้นมีแค่ 4 แถวคีย์ผิด
2. `INVENTSERIALID` มีข้อความ `'NULL'` 116 ล้านแถว · `IS NULL` จับไม่ได้
3. `'PENDING'` เป็น serial ปลอม ใช้ซ้ำ 120,726 ครั้งข้าม 3,847 สินค้า
4. `REFERENCECATEGORY = 7` ไม่ใช่การเคลื่อนไหวจริง ต้องตัดทิ้ง
5. `FO-ITEMNO` บอก BU ไม่ได้ ใช้ `CompanyCode` เท่านั้น
6. การโอน com7 ใช้ `Transfer` · BU อื่นใช้ `shipment` + `receive`
7. ต้นทุนใช้ `RealCost` ตัวเดียว = `POSTED` + `ADJUSTMENT`
8. `DATEPHYSICAL` ไม่มีส่วนเวลา เรียงภายในวันเดียวกันต้องใช้ `InventTrans_RECID`
9. join คลังต้องใช้ `CompanyCode` + `INVENTLOCATIONID` คู่กัน
10. เช็ก `MAX(Transorigin_Sinkdate)` ก่อนส่งรายงาน — drph ช้า 78 วัน · drl ตายแล้ว
