# ขั้น 1 · หางวดแรกที่ยังไม่จ่าย

```sql
WITH first_unpaid AS (
    SELECT CONTRACT_ID, INSTALL_NUM, DUEDATE, RECEIPT_NUMBER
    FROM (
        SELECT CONTRACT_ID, INSTALL_NUM, DUEDATE, RECEIPT_NUMBER,
               ROW_NUMBER() OVER (
                   PARTITION BY CONTRACT_ID
                   ORDER BY CASE WHEN RECEIPT_NUMBER IS NULL THEN 0 ELSE 1 END,
                            CASE WHEN RECEIPT_NUMBER IS NULL THEN  INSTALL_NUM
                                                             ELSE -INSTALL_NUM END
               ) AS rn
        FROM CUSTOMER_CARD
    ) x WHERE rn = 1
)
```

**อ่านทีละบรรทัด**

| บรรทัด | ทำอะไร |
|---|---|
| `PARTITION BY CONTRACT_ID` | จัดกลุ่มทีละสัญญา |
| `ORDER BY CASE WHEN RECEIPT_NUMBER IS NULL THEN 0 ELSE 1` | **งวดที่ยังไม่จ่ายมาก่อนเสมอ** |
| `CASE WHEN ... IS NULL THEN INSTALL_NUM ELSE -INSTALL_NUM` | ถ้ายังไม่จ่าย → เรียงงวดน้อยไปมาก (ได้งวดค้างแรกสุด)<br>ถ้าจ่ายหมด → เรียงกลับด้าน (ได้งวดสุดท้ายที่จ่ายแล้ว) |
| `WHERE rn = 1` | เอาแถวเดียวต่อสัญญา |

**เคล็ดของท่านี้:** ถ้าผลลัพธ์ `RECEIPT_NUMBER IS NULL` = สัญญานั้นยังมีงวดค้างจริง
ถ้าไม่ NULL = จ่ายครบทุกงวดแล้ว → ถูกกรองทิ้งในขั้นถัดไป

> `RECEIPT_NUMBER IS NULL` = **ยังไม่จ่าย** เป็นกฎที่ยืนยันกับทีมแล้ว → [[K2 - Business Rules]]

# ขั้น 2 · คัดสัญญาและแยกกรณี

```sql
DECLARE @snap_1  date = '2026-08-03';   -- วัน refresh ของรอบวันที่ 1
DECLARE @due_1   date = '2026-08-01';
DECLARE @snap_16 date = '2026-08-18';   -- วัน refresh ของรอบวันที่ 16
DECLARE @due_16  date = '2026-08-16';
DECLARE @cut     date = '2026-08-01';
DECLARE @asof    date = '2026-08-18';

picked AS (
    SELECT ct.*, CASE WHEN ct.PERIOD_DUE_DATE IN (@due_1, @due_16) THEN 1 ELSE 2 END AS CASE_NO
    FROM COLLECTION_OD ct
    LEFT JOIN first_unpaid fu ON fu.CONTRACT_ID = ct.CONTRACT_ID
    WHERE fu.RECEIPT_NUMBER IS NULL          -- (ก) ยังมีงวดค้างจริง
      AND ct.CONTRACT_STATUS = 48            -- (ข) ระบบตั้งสถานะ Overdue 6
      AND (                                  -- (ค) ตรงรอบใดรอบหนึ่ง
            ( ct.EXTRACT_DATE = @snap_16 AND ct.PERIOD_DUE_DATE = @due_16 )
         OR ( ct.EXTRACT_DATE = @snap_1  AND ct.PERIOD_DUE_DATE = @due_1  )
         OR ( ct.EXTRACT_DATE = @snap_16 AND ct.PERIOD_DUE_DATE < @cut
              AND DAY(ct.PERIOD_DUE_DATE) = 16 )
         OR ( ct.EXTRACT_DATE = @snap_1  AND ct.PERIOD_DUE_DATE < @cut
              AND DAY(ct.PERIOD_DUE_DATE) = 1 )
          )
)
```

## ทำไมวัน refresh ถึงเป็นวันที่ 3 และ 18

ระบบเปลี่ยนสถานะเป็น Overdue **ช้ากว่าวันครบกำหนดประมาณ 2 วัน** — วัดจากฐานจริง

| วันที่ | สัญญาสถานะ 48 |
|---|---:|
| 2026-08-01 | 6 |
| 2026-08-02 | 6 |
| **2026-08-03** | **337** ← กระโดด |
| 2026-08-04 … 08-17 | 337 → 300 (ลดลงเมื่อลูกค้าจ่าย) |
| **2026-08-18** | **603** ← กระโดด |

→ ถ้าไปดึงวันที่ 1 หรือ 16 จะได้แค่ 6 สัญญา **ต้องดึงวันที่ 3 กับ 18**

## 2 กรณีต่างกันตรงไหน

| | กรณี 1 · OD6 ปกติ | กรณี 2 · สัญญาหมดอายุแล้ว |
|---|---|---|
| เงื่อนไข | `PERIOD_DUE_DATE` = วันครบกำหนดของรอบนั้น | `PERIOD_DUE_DATE` **< 2026-08-01** |
| หมายความว่า | งวดที่เพิ่งถึงกำหนดยังไม่จ่าย · สัญญายังเดินอยู่ | งวดถัดไปอยู่ในอดีต = สัญญาจบแล้วแต่ยังค้าง |
| จำนวน | 465 (รอบ 1 = 236 · รอบ 16 = 229) | 155 (รอบ 1 = 74 · รอบ 16 = 81) |

**`DAY(PERIOD_DUE_DATE)` ใช้แยกว่าสัญญานั้นอยู่รอบวันที่ 1 หรือ 16**
ป้องกันไม่ให้สัญญาเดียวถูกหยิบซ้ำจากทั้งสอง snapshot — **ทดสอบแล้วไม่มีสัญญาซ้ำจริง**

# ขั้น 3 · สรุปการ์ดผ่อน — หัวใจของตัวเลขทุกตัว

```sql
card AS (
    SELECT CONTRACT_ID,
           COUNT(*)                                                   AS N_CARD,
           MAX(INSTALL_NUM)                                           AS LAST_INSTALL_NUM,
           MAX(DUEDATE)                                               AS CONTRACT_LAST_DUE,
           MIN(CASE WHEN RECEIPT_NUMBER IS NULL THEN INSTALL_NUM END) AS FIRST_UNPAID_NUM,
           MIN(CASE WHEN RECEIPT_NUMBER IS NULL THEN DUEDATE END)     AS FIRST_UNPAID_DUE,
           MAX(CASE WHEN RECEIPT_NUMBER IS NULL AND DUEDATE <= @asof
                    THEN INSTALL_NUM END)                             AS LAST_PASTDUE_NUM,
           MAX(CASE WHEN RECEIPT_NUMBER IS NULL AND DUEDATE <= @asof
                    THEN DUEDATE END)                                 AS LAST_PASTDUE_DUE,
           SUM(CASE WHEN RECEIPT_NUMBER IS NULL AND DUEDATE <= @asof
                    THEN 1 ELSE 0 END)                                AS N_PASTDUE,
           SUM(CASE WHEN RECEIPT_NUMBER IS NULL AND DUEDATE <= @asof
                    THEN INSTALL_AMT END)                             AS OD_AMT_CARD
    FROM CUSTOMER_CARD GROUP BY CONTRACT_ID
)
```

## ⚠️ `DUEDATE <= @asof` สำคัญมาก

งวดในอนาคตยังไม่มีใบเสร็จ = ถูกนับเป็น "ค้าง" ถ้าไม่กรอง

| สัญญา `24138408` | ค่า |
|---|---:|
| งวดที่ยังไม่จ่ายทั้งหมด | **8** |
| งวดที่**เลยกำหนดแล้ว**และยังไม่จ่าย | **7** |

งวดที่ 24 ครบกำหนด 2026-09-16 ยังไม่ถึง → **ไม่ใช่งวดค้าง**
ถ้าไม่ใส่ `DUEDATE <= @asof` จะได้จำนวนงวดค้างเกินจริงและยอดเงินเกินจริง

# ขั้น 4 · งวดที่ครบ OD 6

**ใช้สูตรของ template** = `MIN(ค้างงวดแรก + 5, จำนวนงวดทั้งหมด)`

```sql
CASE WHEN cd.FIRST_UNPAID_NUM + 5 > cd.LAST_INSTALL_NUM
     THEN cd.LAST_INSTALL_NUM
     ELSE cd.FIRST_UNPAID_NUM + 5 END AS [งวดที่ครบ OD 6]
```

ตรวจกับตัวอย่างในเทมเพลตแล้วตรงทุกแถว: ค้างงวดแรก 4 → OD6 = 9 · ค้างงวดแรก 1 → 6 · ค้างงวดแรก 6 → 11
และเคสที่สัญญามี 24 งวด ค้างงวดแรกที่ 22 → **ตัดที่ 24 ไม่ใช่ 27**

> **สูตรนี้ไม่แม่นกับคนที่จ่ายๆ หยุดๆ** เพราะสมมติว่าค้างต่อเนื่อง 6 งวดรวด
> ตัวเลขที่นับจากงวดค้างจริงลำดับที่ 6 อยู่ในชีต `ตรวจสอบ` คอลัมน์ `_งวดค้างเกินกำหนดลำดับที่6`

# ขั้น 5 · คำนวณค่าธรรมเนียมตาม Fee Policy

## ค่าเบี้ยปรับชำระล่าช้า — 100 บาท/งวด เพดาน 600

```sql
100 * (CASE WHEN cd.N_PASTDUE >= 6 THEN 6 ELSE cd.N_PASTDUE END)
```

| งวดค้าง | 1 | 2 | 3 | 4 | 5 | 6 | 7+ |
|---|---:|---:|---:|---:|---:|---:|---:|
| ค่าปรับ | 100 | 200 | 300 | 400 | 500 | **600** | 600 |

## ค่าติดตามทวงถามหนี้ — แยก 2 กรณี

### ⚠️ เกณฑ์ตัดสิน A/B ต้องรวมค่าปรับด้วย

**ยอดที่เอาไปเทียบกับ 1,000 บาท = ค่างวด + ค่าปรับ 100 บาท**

```sql
WHEN ISNULL(pd.INSTALL_SUM, 0) + 100 > 1000   -- ← เส้นแบ่งอยู่ที่ค่างวด 900 ไม่ใช่ 1,000
```

| ค่างวด | ยอดค้างงวดแรก | เกณฑ์ |
|---:|---:|---|
| 903.05 | **1,003.05** | Case A |
| 900 | 1,000 | Case B |
| 401 | 501 | Case B |

**เคสตรวจสอบ `25272055`** — ค่างวด 903.05 · ค้าง 6 งวด → Case A → OD5+ → **450** ✅

### กรณี A · ค่างวด + 100 > 1,000

```sql
CASE WHEN cd.N_PASTDUE >= 5 THEN 450
     ELSE 50 + (cd.N_PASTDUE - 1) * 100 END
```

| งวดค้าง | 1 | 2 | 3 | 4 | 5+ |
|---|---:|---:|---:|---:|---:|
| ค่าติดตาม | 50 | 150 | 250 | 350 | **450** |

งวดแรกคิด 50 · งวดถัดไปคิด 100 · ถึง OD5 แล้วไม่เก็บเพิ่ม

### กรณี B · ค่างวด + 100 ≤ 1,000

ยอดสะสมหลังผ่านไป k งวด = **k × (ค่างวด + 100)**
คิด **+100 ต่อลำดับงวดที่ยอดสะสมเกิน 1,000 บาท** นับถึง OD5 แล้วหยุด

```sql
100 * MAX(0, MIN(N_PASTDUE, 5) - k0 + 1)

โดย  k0 = FLOOR(1000 / (ค่างวด + 100)) + 1     -- งวดแรกที่ยอดสะสมเกิน 1,000
```

**ตัวอย่างจากเอกสารนโยบาย — คุณสมหญิง ค่างวด 300 บาท**

| ขั้น OD | ค่างวดสะสม | ค่าปรับสะสม | ยอดค้างสะสม | เกิน 1,000? | ลำดับ | ค่าติดตาม |
|---|---:|---:|---:|:--:|---:|---:|
| OD 1 | 300 | 100 | 400 | ✗ | – | – |
| OD 2 | 600 | 200 | 800 | ✗ | – | – |
| **OD 3** | 900 | 300 | **1,200** | ✓ | 1 | **100** |
| OD 4 | 1,200 | 400 | 1,600 | ✓ | 2 | 200 |

ตรวจสูตร: `k0 = FLOOR(1000 / (300+100)) + 1 = FLOOR(2.5) + 1 = 3` → ที่ OD3 ได้ลำดับ 1 ✓

## ค่าใช้จ่ายอื่นตามกฎหมาย = 0

ทุกรายในตัวอย่างที่ทีมเคยกรอกเป็น 0 และหาคอลัมน์ที่ตรงกันในฐานไม่เจอ → ใส่ 0 คงที่

## รวมเป็นเงินทั้งสิ้น

```
ค่าเช่าซื้อที่ค้างชำระ + ค่าเบี้ยปรับ + ค่าติดตาม + ค่าใช้จ่ายอื่น
```

# เส้นทาง join ที่ใช้ประกอบข้อมูล

```
COLLECTION_OD (คัดรายชื่อ)
   └─ CONTRACT_ID ──► CONTRACT ──► PERSON_ID ──► PERSON ──► MT_PREFIX     ชื่อ + คำนำหน้า
                          │                        └─────► ADDRESS        ที่อยู่ชุด A1
                          │                                   ├─► MT_PROVINCE
                          │                                   ├─► MT_DISTRICT
                          │                                   └─► MT_SUB_DISTRICT
                          ├─ PRODUDCT_ID ──► PRODUCT ──► MT_BRAND         เครื่อง + เงื่อนไขการเงิน
                          │                     └──────► MT_CATEGORY
                          └─ CONTRACT_ID ──► CUSTOMER_CARD                งวด + ยอดเงิน
```

**ทดสอบแล้วจับคู่ได้ 100% ทุกเส้นทาง** — `CONTRACT` · `PERSON` · `ADDRESS` · `PRODUCT` · `CUSTOMER_CARD` ไม่มีแถวหลุด

## กับดักที่ต้องระวังตอน join

| เรื่อง | ต้องทำ |
|---|---|
| `PREFIX` · `PRODUCT_BAND` · `PRODUCT_CATEGORY` · `A1_PROVINCE` เก็บรหัสเป็น**ข้อความ** | ต้อง `TRY_CAST(... AS int)` ก่อน join |
| `PRODUDCT_ID` สะกดผิดในฐาน | ใช้ตามชื่อจริง |
| `PRODUCT_BAND` ที่จริงคือ BRAND | ใช้ตามชื่อจริง |
| `CONTRACT.SERIAL_NUMBER` ว่างทั้งตาราง | ต้องใช้ `PRODUCT.SERIAL_NUMBER` |
| `PRODUCT.INSTALL_AMT` เป็นยอด**ก่อน** VAT | ต้องใช้ `INSTALL_SUM` ที่รวม VAT แล้ว |
| `FRIST_PAY_DATE` สะกดผิดในฐาน | ใช้ตามชื่อจริง |

```sql
         ELSE N'เลขที่ ' + a.A1_NO + N' ' END
  + CASE WHEN NULLIF(LTRIM(RTRIM(a.A1_MOI)),N'') IS NULL THEN N''
         ELSE N'หมู่ที่ ' + a.A1_MOI + N' ' END
  + ...   -- หมู่บ้าน/โครงการ · อาคาร · ชั้น · เลขที่ห้อง · ซอย · ถนน
))
```

**ช่องไหนว่างให้ตัดทั้งท่อนรวมป้ายกำกับ** ไม่ใช่ปล่อยป้ายลอย

| คอลัมน์ | ประกอบจาก |
|---|---|
| `เลขที่` (AE) | `A1_NO` · `A1_MOI` · `A1_VILLAGE` · `A1_BUILDING` · `A1_FLOOR` · `A1_ROOM_NO` · `A1_SOI` · `A1_ROAD` |
| `แขวง/ตำบล/อำเภอ` (AF) | `'ตำบล' + SUB_DISTRICT_NAME + ' อำเภอ' + DISTRICT_NAME` |
| `จังหวัด` (AG) | `MT_PROVINCE.PROVINCE_NAME` |
| `รหัส ปณ.` (AH) | `A1_POSTALCODE` |
| `ที่อยู่ตามทะเบียนบ้าน` (AD) | **AE + AF + AG + AH ต่อกันด้วยช่องว่าง** |

ใช้ที่อยู่ **ชุด A1 = ตามทะเบียนบ้าน** — `ADDRESS` มี 5 ชุด (ทะเบียนบ้าน · ปัจจุบัน · ติดต่อได้ · จัดส่ง · ที่ทำงาน)
**ยังไม่ได้ยืนยันกับทีมว่าส่งจริงใช้ชุดไหน** → [[Collection Team Questions]]

# ⚠️ รายชื่อไม่นิ่ง — ต้องรันใกล้วันออกหนังสือ

`COLLECTION_OD` เป็น snapshot ตรึงไว้ ณ วันนั้น แต่ **`CUSTOMER_CARD` เป็นข้อมูลสด**
เมื่อลูกค้าจ่ายเงิน `RECEIPT_NUMBER` ถูกเติมย้อนไปที่งวดเดิม → ผลลัพธ์เปลี่ยน

**หลักฐาน:** รัน query เดียวกันห่างกันไม่กี่วัน ได้ **621 → 620** สัญญา
สัญญาที่หายไป: `24106596` จ่ายครบระหว่างสองครั้งที่รัน

และในรอบล่าสุดมี **3 สัญญาที่ไม่เหลืองวดค้างเกินกำหนดแล้วเลย** — `26276669` · `24151264` · `24147020`
snapshot วันที่ 18 ส.ค. ยังบอกว่าค้าง แต่การ์ดผ่อนวันนี้จ่ายครบแล้ว → **ยอดเรียกเก็บเป็น 0 ทุกช่อง**

### ตัดออกด้วย `WHERE cd.N_PASTDUE > 0`

```sql
/* ตัดสัญญาที่ไม่เหลืองวดค้างเกินกำหนดแล้ว — จ่ายครบหลังวัน snapshot
   ยอดเรียกเก็บจะเป็น 0 ทุกช่อง ออกหนังสือไม่ได้ */
WHERE cd.N_PASTDUE > 0
```

**620 → 617 สัญญา** (กรณี 1 จาก 465 → 462 · กรณี 2 คงเดิม 155)

ตรวจแล้วในไฟล์ผลลัพธ์: **แถวที่ยอดรวมเป็น 0 หรืองวดค้างเป็น 0 = 0 แถว**
งวดค้างต่ำสุด = **1 งวด** · ยอดรวมต่ำสุด = **771.19 บาท**

**ยังต้องมีขั้นตอนตรวจซ้ำก่อนส่ง** เพราะระหว่างวันที่รันกับวันที่ส่งหนังสือ อาจมีคนจ่ายเพิ่มอีก

## v4 — ไม่ต้องรอวัน refresh อีกแล้ว (2026-08-31)

เดิมสคริปต์ต้องไปหาวันที่ระบบ refresh สถานะ OD (วันที่ 3 และ 18) แล้วอ่านจาก snapshot วันนั้น
**v4 เลิกใช้ snapshot ทั้งหมด** — นับงวดที่ยังไม่มีใบเสร็จจาก `CUSTOMER_CARD` ตรง ๆ

```sql
HAVING SUM(CASE WHEN RECEIPT_NUMBER IS NULL AND DUEDATE <= @asof
                THEN 1 ELSE 0 END) >= 6
```

การ์ดอัปเดตทันทีที่รับชำระ **รันวันไหนก็ได้ภาพของวันนั้นเสมอ** จะรันวันที่ 5, 20 หรือสิ้นเดือนก็ได้ผลตรงกับความจริง ณ วันที่รัน

ทำไมถึงเปลี่ยน — รายชื่อรอบ 8/2026 มี **204 จาก 617 ราย** ที่ค้างจริงไม่ถึง 6 งวด
เหตุผลเต็มอยู่ใน [[K2 - OD6 Selection Logic]] หัวข้อ v4

### SQL v4 ฉบับสมบูรณ์ (คัดรายชื่อ + คำนวณยอดจากการ์ด)

> รันวันไหนก็ได้ · ไม่ต้องรอ refresh 3/18 · ยอดตรงกับความจริง ณ วันที่รัน
> บันทึก 2026-09-16 · แทนที่ `k2_termination_list_v2.sql` (เก่า)

```sql
DECLARE @asof date = CAST(GETDATE() AS date);   -- รันวันไหนก็ได้ (ค้างจริง ณ วันนี้)

WITH card AS (
    -- สรุปการ์ดลูกหนี้ต่อสัญญา: นับงวดที่ยังไม่มีใบเสร็จ ถึงวันที่รัน
    SELECT CONTRACT_ID,
           COUNT(*)                                                    AS N_CARD,
           MAX(INSTALL_NUM)                                            AS LAST_INSTALL_NUM,
           MIN(CASE WHEN RECEIPT_NUMBER IS NULL THEN INSTALL_NUM END)  AS FIRST_UNPAID_NUM,
           MIN(CASE WHEN RECEIPT_NUMBER IS NULL THEN DUEDATE END)      AS FIRST_UNPAID_DUE,
           SUM(CASE WHEN RECEIPT_NUMBER IS NULL AND DUEDATE <= @asof
                    THEN 1 ELSE 0 END)                                 AS N_PASTDUE,
           SUM(CASE WHEN RECEIPT_NUMBER IS NULL AND DUEDATE <= @asof
                    THEN INSTALL_AMT ELSE 0 END)                       AS OD_AMT_CARD
    FROM CUSTOMER_CARD
    GROUP BY CONTRACT_ID
)
SELECT ct.CONTRACT_NUMBER,
       ct.CONTRACT_ID,
       cd.FIRST_UNPAID_NUM,
       cd.N_PASTDUE,
       -- งวดที่ครบ OD6 (ไม่เกินงวดสุดท้ายของสัญญา)
       CASE WHEN cd.FIRST_UNPAID_NUM + 5 > cd.LAST_INSTALL_NUM
            THEN cd.LAST_INSTALL_NUM
            ELSE cd.FIRST_UNPAID_NUM + 5 END                           AS [งวดที่ครบ OD 6],
       cd.OD_AMT_CARD                                                  AS [ยอดค้างจากการ์ด]
FROM CONTRACT ct
JOIN card cd ON cd.CONTRACT_ID = ct.CONTRACT_ID
-- เกณฑ์ v4: ค้างจริง >= 6 งวด นับจากการ์ด (ไม่ใช้ CONTRACT_STATUS=48 / snapshot)
WHERE cd.N_PASTDUE >= 6
ORDER BY ct.CONTRACT_NUMBER;
```

**ต่างจาก v2 ตรงไหน:**
| | v2 (เก่า) | v4 (นี้) |
|---|---|---|
| แหล่งงวดค้าง | `COLLECTION_OD` snapshot (refresh 3/18) | `CUSTOMER_CARD` นับตรง |
| เกณฑ์คัด | `CONTRACT_STATUS = 48` | `N_PASTDUE >= 6` (นับจริง) |
| วันรัน | ต้องตรงวัน refresh | รันวันไหนก็ได้ |
| ยอดในหนังสือ | `OD_AMOUNT` (snapshot) | `OD_AMT_CARD` (จากการ์ด) |

> คอลัมน์สำหรับกรอกหนังสือบอกเลิก → ดู [[K2 - Termination Letter Mapping]] (column R ต้องใช้ `OD_AMT_CARD` ตาม v4 นี้)

## ดูภาพย้อนหลังยังทำได้

`--asof` ย้อนหลังได้ตามต้องการ — แต่ได้ภาพ **การ์ด ณ วันนี้** ที่ตัดงวดตามวันที่ระบุ
ไม่ใช่ภาพจริง ณ วันนั้น เพราะการ์ดไม่เก็บประวัติว่าเมื่อวานยังไม่จ่าย

```powershell
python scripts/k2/k2_termination.py 2026-07 --asof 2026-07-31
```

**ถ้าต้องการภาพจริงย้อนหลัง** ต้องกลับไปอ่าน `COLLECTION_OD` ที่ `EXTRACT_DATE` วันนั้น ซึ่ง v4 ไม่ทำให้แล้ว
